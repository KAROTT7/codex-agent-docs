# 前端总则

- 先确认应用归属、框架、路由、状态管理、请求库、表单库、样式方案和测试命令。
- 遵循现有框架约定，优先复用组件、hooks、utils、类型和主题变量。
- 服务端数据与本地 UI 状态分离；请求处理加载、异常、空数据、并发和卸载逻辑，错误与重试界面的展示遵循下方 UI 规则。
- 关注语义标签、禁用态和响应式边界。
- 不启动开发服务器，除非用户明确要求或验证确实需要。
- 按改动风险选择最小必要验证：未新增或删除依赖、未修改项目配置文件且不影响构建产物时，默认执行相关 lint、typecheck 和测试即可；涉及依赖、项目配置文件、入口文件、环境变量、代码分割、资源处理或其他可能影响产物的改动时，再执行 build。微信小程序同样遵循此规则。

## UI 状态与数据兜底

- 文案和视觉状态以需求为准，不自行添加操作教程、功能说明、提示横幅或装饰性模块；已有设计稿时遵循其中的文案与状态，仅补充完成业务流程所必需的反馈。
- 页面或组件的需求、设计未明确要求错误状态或重试交互时，不额外展示错误面板、失败占位或重试按钮。
- 接口错误提示沿用统一请求层，页面不重复弹出相同提示。
- 接口请求失败时，可以按接口数据类型为展示数据提供兜底，例如数组类型使用 `[]`；其他类型仅使用符合类型约束和业务含义的空值，不用 `{}` 等不完整对象冒充有效数据。
- 数据兜底仅用于页面展示，保留现有请求层的异常处理机制，不将提交、支付等操作失败当作成功处理。
