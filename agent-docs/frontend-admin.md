# 管理后台

本规范适用于前端管理后台应用，沿用前端总则。

- 沿用项目现有表单方案，不在同一页面混用两套表单状态源。

## 列表页

- 将已生效的表单筛选条件、当前页码和每页条数同步到 URL 查询参数，作为列表查询状态的恢复依据。
- URL 参数按字段类型解析；非法页码、每页条数使用项目约定的默认值。
- 首次进入、刷新页面及浏览器前进 / 后退时，从 URL 恢复筛选表单、分页控件和列表查询参数，确保三者一致；跳转详情等页面后返回列表时，保留原列表的查询参数。
- 提交筛选或重置筛选时，将页码重置为第一页，并同步更新 URL 与列表查询；重置仅清除本列表管理的筛选参数，保留其他业务参数。表单尚未提交的输入不作为已生效筛选条件写入 URL。
- 优先复用项目现有路由和 URL 状态管理能力，避免 URL、组件状态和缓存各自维护一套独立的列表查询状态。

## 操作确认

- 删除、审核（通过或驳回）操作必须提供二次确认，批量操作同样适用；仅在用户确认后发起请求，取消时不执行操作。
- 已有审核或删除弹窗明确展示操作对象与结果，并要求用户确认提交时，即视为完成二次确认，不再叠加确认弹窗。
- 优先复用项目现有的确认弹窗或气泡确认组件，明确提示操作对象、审核结果或批量操作数量；请求期间禁用重复提交。
